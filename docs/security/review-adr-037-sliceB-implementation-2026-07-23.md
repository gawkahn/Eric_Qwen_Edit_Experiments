## Threat model and review approach

Adversaries: (a) a steered judge LLM whose verdict is the only planner channel; (b) crafted seed images/sidecars (F4); (c) injection text rendered into images the multimodal judge reads — which slice B makes *persistent* via the accepted source (F8-E); and, newly load-bearing for this slice, (d) a misbehaving or stale daemon on the Unix socket, because the slice adds a daemon-response-keyed control-flow branch (`error_type=="RefPathError"` → in-process latch). The daemon is operator-owned (ADR-001) and more trusted than a seed sidecar, but its wire strings now drive both a loud notice and a mode switch, so I treated its responses as semi-trusted. The security surface audited: the edit-mode entry contract (can any file-derived byte reach the family gate or the config), every write to `current_source`, the two-image judge payload (any path/filename/stem in wire text), the ref-spec typed channel in both daemon and cold directions, the RefRefusedError latch semantics vs the design-review Finding-2 remediation intent, history-record shape, and the recipe/contract split.

## Findings

**[LOW] 1 — Daemon-controlled error text echoed raw in the RefRefusedError loud notice (and the fatal daemon-error path)**
Location: `comfyless/refine.py:1419` (`({e})` in the latch notice; message set from `resp.get("error", ...)` at 1230; same pattern at 1231–1232 → `main` 2197)
Risk: The daemon's `error` string is interpolated unescaped into terminal output; embedded ANSI escapes or newlines could corrupt the terminal or spoof `[refine]` log lines during an unattended run. Requires a hostile/compromised daemon (operator-owned Unix socket — named assumption: socket perms per ADR-001 hold), but MEDIUM-1 of the ADR-035 slice-5 review set the precedent of `repr()` on any echoed string of non-typed provenance, and the legit daemon message embeds a path either way. 1231→2197 is a pre-existing slice-3 pattern; the latch notice at 1419 is new slice-B code.
Remediation: `({e!r})` in the 1419 notice (and, opportunistically, `{resp.get('error', ...)!r}` at 1230/1232).

**[LOW] 2 — Refine's daemon edit path inherits TTY-keyed lenient `ref_drop_strict` and never surfaces wire `edit_warnings` — a divergent/stale daemon could silently drop the edit source**
Location: `comfyless/refine.py:1216–1254` (no `ref_drop_strict` forcing; `resp["metadata"]` consumed without surfacing `edit_warnings`), interacting with `generate.py:3085–3091`
Risk: `_build_server_request` sends `ref_drop_strict=False` whenever stdin is an interactive TTY — the CLI-appropriate default, but wrong for a machine loop whose cold path deliberately pins `ref_drop_strict=True` (1308). If the daemon ever family-gates the ref out (reachable only via daemon/client version or detection divergence — e.g. a stale daemon, a scenario this file already designs for at 1238–1251), a lenient drop returns `status=ok` with the warning in `metadata["edit_warnings"]` — which `_delegate_to_server` surfaces (generate.py:3200–3201, invariant N1) but refine does not. The iteration then silently degrades to t2i-from-prompt while the judge is shown a "SOURCE vs CANDIDATE" edit framing, scores garbage, and a scene-unlocked image can be promoted into the keyframe lineage with a lying audit trail. Assumption I could not verify without daemon-version archaeology: whether a pre-slice-4 daemon rejects the unknown `ref_images` key (fail-closed) or ignores it (same silent degrade with no warning at all).
Remediation: In `run_generation`'s daemon branch, force `req["ref_drop_strict"] = True` when `ref_images` is non-empty (one line after `_build_server_request`), and echo `resp["metadata"].get("edit_warnings")` through `log` (mirrors the N1 surfacing in `_delegate_to_server`).

**[LOW] 3 — Judge-source re-open is uncapped: `Image.open(current_source)` bypasses the F5/ref caps every iteration**
Location: `comfyless/refine.py:1459`
Risk: The seed is F5-capped once at entry (2142) and the *generation* read of `current_source` is re-capped every iteration (`load_ref_image_capped` cold / daemon-side ingestion), but the judge-source open at 1459 does a full decode with no byte/pixel/format gate. The TOCTOU window spans the whole GPU generation (minutes): a file swapped in during that window is decoded unbounded (only PIL's mutable process-global bomb guard applies — which this module's own F5 comment says it refuses to rely on) and its pixels ship to the judge, an uncapped-payload + visual-injection variant of F8-E. Exploitation requires local write access to the seed path or `candidates/` — operator-equivalent on this solo desktop — so this is a hygiene/consistency finding, not a live exploit.
Remediation: Open the judge source through the existing capped loader (`load_seed_image_capped(current_source)` — it returns the RGB PIL directly) instead of bare `Image.open`.

**[LOW] 4 — The RefPathError→RefRefusedError wire keying is untested: the fakes replace `run_generation` wholesale**
Location: `comfyless/refine.py:1224–1232` (untested branch); `test_refine.py:1736–1750` (`_FakeGenE` bypasses it)
Risk: The security-relevant discriminator — `error_type=="RefPathError"` recovers in-process, while a weight-path `PathError` (or any other daemon error) stays FATAL and must never retry in-process past daemon weight containment — has zero pins. A future edit that loosens the comparison (substring match, or catching `PathError` too) would reopen exactly the fallback the design review's Finding-2 prohibition text warns about, with green tests.
Remediation: One monkeypatched-`_send_server_command` test pair: daemon resp `{"status":"error","error_type":"RefPathError",...}` → `RefRefusedError`; `{"error_type":"PathError",...}` → plain fatal `RefineError` (no in-process generation observed).

**[LOW] 5 — No negative pinning "edit mode never reads embedded seed params": the test seed is a chunk-less PNG**
Location: `test_refine.py:1683–1716` (gap)
Risk: The Finding-5 pixels-only contract currently holds by construction (the edit branch calls only `load_seed_image_capped`), but every entry-contract test seeds with a bare 8×8 PNG. A regression that re-introduces param extraction in edit mode — e.g. a future "convenience" merge of seed gen-params — would reopen the F4 channel into the family-gated config with zero red tests. This is the same shape as slice-A's LOW-2 (constraint enforced by construction, no sentinel).
Remediation: One main-level test: a seed PNG carrying an embedded comfyless chunk with sentinel `model`/`prompt`/`steps`; run the edit entry path (stub the loop) and assert the sentinels appear nowhere in the built config or target prompt.

**[INFO] 6 — ADR-037 D5 text still mandates the loop-entry preflight the implementation deliberately replaced**
Location: `docs/decisions/ADR-037-refine-loop-v2-trajectory-edit.md` D5 ("at loop entry … preflights … decided once, before any GPU work") vs `refine.py:1414–1432`
Risk: The first-refusal latch is a sound — arguably strictly better — realization of the Finding-2 remediation (assessed above), but the accepted decision text now describes a mechanism that does not exist and cannot (ADR-035 4b). Unrecorded, the divergence invites a future session to "fix" the code back toward an unimplementable preflight, or to read the latch as unauthorized drift.
Remediation: ADR-037 Changelog entry (append-only, §12): slice B implements Finding 2 as first-refusal latching keyed on wire `error_type=="RefPathError"`, superseding the D5 preflight sentence; prohibited workarounds unchanged; note the mid-run daemon→in-process split is covered by the LOW-7 param-forwarding parity.

**[INFO] 7 — t2i runs catch `RefRefusedError` but do not persist the latch; the notice text misdescribes both cases**
Location: `comfyless/refine.py:1403–1408` (t2i `gen_kwargs` rebuilt without `force_in_process`), 1419–1424 ("WHOLE run in-process")
Risk: A daemon spuriously emitting `RefPathError` on ref-less t2i requests causes a safe but wasteful daemon-attempt-then-in-process cycle *every* iteration (the latch is set but only read in the edit branch), each printing an edit-source-worded notice in a run with no edit source. In edit mode the notice's "WHOLE run" overstates: prior iterations may already have run on the daemon. No security impact; loop remains bounded.
Remediation: Optional — apply `force_in_process=in_process_latch` in the t2i `gen_kwargs` too, and reword to "the rest of the run".
